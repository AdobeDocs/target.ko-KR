# [!UICONTROL 다변량 테스트] 모범 사례 {#mvt-best-practices}

>[!BEGINSHADEBOX]

**이 페이지에서:** **[!UICONTROL 다변량 테스트]** 활동을 계획, 만들고, 분석하고, 후속 작업을 수행하여 신뢰할 수 있는 결과를 얻는 방법에 대해 알아봅니다.

>[!ENDSHADEBOX]

다음 팁을 통해 성능을 개선하고 문제를 방지하며 [!DNL Adobe Target]에서 **[!UICONTROL 다변량 테스트]**(MVT) 활동을 만들고 실행할 때 발생할 수 있는 알려진 문제를 해결할 수 있습니다.

## 계획 {#plan}

* **테스트에서 세 개 이상의 요소를 사용합니다.**

  테스트할 요소가 3개 미만이면 일련의 A/B 테스트를 실행합니다. 자세한 내용은 [다변량 테스트와 A/B를 사용해야 하는 경우](/help/main/c-activities/c-multivariate-testing/multivariate-testing.md#when-to-use-mvt)를 참조하십시오.

* **노출 및 전환 수를 포함하여 일반적으로 받는 트래픽의 양에 주의하십시오.**

  MVT에는 유용한 결과를 얻기에 충분한 트래픽이 필요하며, 이 정보는 사이트의 트래픽을 초과하는 요구 사항을 사용하여 테스트를 디자인할 가능성을 줄이는 데 도움이 됩니다.

* **유효한 결과를 생성할 수 있는 페이지의 위치를 파악합니다.**

  배너 또는 영웅 이미지는 바닥글을 변경하는 것보다 더 많은 전환을 초래할 수 있습니다. 영향력이 적은 위치를 테스트에 포함하면 페이지에서 더 중요한 위치를 테스트하는 데 필요한 트래픽과 시간만 늘어날뿐입니다.

* **요소를 서로 독립적으로 유지합니다.**

  예를 들어 동일한 테스트에서 레이아웃과 콘텐츠를 테스트하지 마십시오.

* **테스트할 페이지의 HTML 코드를 검사합니다.**

  사이트의 HTML 요소에 중복 DOM ID가 없는지 확인합니다. ID가 중복되면 동일한 콘텐츠가 여러 위치에 전달될 수 있습니다.

* **미리 페이지 변형을 준비합니다.**

  각 오퍼의 콘텐츠 차이점을 파악하고 MVT 테스트에 사용할 이미지, 텍스트, HTML 오퍼를 만듭니다.

* **추가 QA 시간을 계획합니다.**

  경험 수가 증가하므로 QA에 더 많은 시간이 소요됩니다.

## 생성하기 {#create}

* **테스트에 필요한 것보다 더 많은 조합을 포함하지 마십시오.**

  테스트하는 조합이 많을수록 허용되는 결과를 얻는 데 필요한 트래픽과 시간이 대폭 증가합니다. 예를 들어, 3개 위치에 오퍼가 3개씩 포함되어 있으면 총 27개의 조합을 만들 수 있습니다(3x3x3). 3개 위치 중 2개 위치에는 3개의 오퍼가 포함될 수 있으며 1개 위치에는 2개의 오퍼가 포함될 수 있으므로 총 18개의 옵션이 제공됩니다(3x3x2). 이 수치는 위치 및 오퍼가 추가될 때마다 현저히 증가합니다.

* **위치 및 오퍼 이름을 지정합니다.**

  테스트에서 각 위치와 오퍼를 좀 더 편리한 이름으로 바꿀 수 있습니다. 각 위치에 있는 오퍼의 수는 위치 헤더에 나타납니다. 유용한 이름은 보고서를 검토할 때 오퍼를 식별하는 데 도움이 됩니다.

* **미리 보기 기능을 활용하여 불필요한 콘텐츠 조합을 방지할 수 있습니다.**

  테스트에서 생성된 모든 경험을 검토한 후에 적용합니다. 청구가 모순되거나(예: 동일한 경험에서 20% 할인 및 $19 할인) 배경색 및 글꼴과 같은 호환되지 않는 디자인이 조합되지 않았는지 확인하십시오.

* **[트래픽 견적 도구](/help/main/c-activities/c-multivariate-testing/t-create-multivariate-test/traffic-estimator.md#traffic-estimator)를 사용하여 페이지에 수신되는 트래픽 양에 맞게 테스트를 디자인할 수 있습니다.**

  **[!UICONTROL 트래픽 견적 도구]**&#x200B;가 테스트 구성에 녹색 표시등을 제공하므로 원하는 결과를 얻을 수 있습니다.

* **각 요소의 대체 요소를 서로 크게 다르게 만드십시오.**

  필수는 아니지만 각 요소가 동일한 수의 대안을 갖는 것이 좋습니다.

## 분석 {#analyze}

* **[위치 기여도 보고서](/help/main/c-reports/multivariate-test-reports/location-contribution-report.md)**&#x200B;를 자주 사용하여 각 위치와 오퍼의 성능을 모니터링합니다.

* **경험 성과 보고서[&#128279;](/help/main/c-reports/multivariate-test-reports/experience-performance-report.md)에서 [!UICONTROL 최고 성과 보고서] 및 [!UICONTROL 최저 성과 보고서] 필터를 사용하여 표시되는 데이터를 결정합니다.**

  **[!UICONTROL 모두]** 필터를 사용하면 원하는 정보를 추출하기 어려우며 일부 경험은 그래프에 표시되지 않을 수 있습니다. 성과가 가장 높은 경험 5개 또는 가장 낮은 경험 5개에 포함되지 않은 특정 경험을 확인하려는 경우에는 **[!UICONTROL 모두]** 필터를 사용하십시오.

## 추가 작업 {#follow-up}

* [!DNL Target]에서 실시간 활동을 편집할 수 있지만 **진행 중인 활동을 편집하면 테스트가 재설정될 수 있습니다.** 보고서가 일부 변경 사항을 인식하지 못할 수 있습니다. 오퍼 라이브러리에서 HTML 오퍼를 변경하는 것만이 안전합니다.

  경험 이름 및 보고서를 재설정하는 특정 작업은 다음과 같습니다.

  * 새 위치 추가
  * 위치 삭제
  * 새 오퍼 추가 또는 기존 위치에서 오퍼 삭제
  * 서식 있는 텍스트 오퍼 편집
  * 배경색 오퍼 편집

* **[!DNL Analytics] 기반 지표(회전자가 표시됨)를 사용하는 활동을 편집할 때 보고서 세트가 로드되지 않으면** 지표를 [!DNL Target] 지표로 전환한 다음 [!DNL Analytics] 기반 지표로 다시 전환합니다. 이제 보고서 세트가 로드됩니다.

* **하나 이상의 A/B 테스트로 MVT 테스트를 실행합니다**. 원하는 결과에 가장 적합한 콘텐츠를 결정합니다. 목표 달성에 가장 유용한 위치 및 콘텐츠를 파악한 후에는 A/B 테스트를 실행하여 결과를 세분화할 수 있습니다. 예를 들어 어떤 위치가 가장 중요한지 알고 있는 경우 두 개의 특정 이미지를 서로 테스트하거나 call to action의 단어 또는 색상을 비교합니다.
