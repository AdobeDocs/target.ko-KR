# [!UICONTROL 다변량 테스트] 시작 {#get-started-mvt}

>[!BEGINSHADEBOX]

**이 페이지에서:** [!DNL Target]에서 사용하는 **[!UICONTROL 다변량 테스트]**&#x200B;가 작동하는 방식, A/B 테스트 대신 사용할 시점 및 부분 요인 테스트가 트래픽 요구 사항을 줄이는 방법에 대해 알아봅니다.

>[!ENDSHADEBOX]

[!DNL Adobe Target]의 **[!UICONTROL Multivariate Test]**(MVT) 활동은 페이지의 요소 간에 오퍼 조합을 비교하여 특정 대상에 가장 뛰어난 조합을 결정합니다. 또한 활동의 성공에 가장 큰 영향을 미치는 요소를 식별하는 데 도움이 됩니다. 다변량 테스트는 페이지의 다른 요소와 비교하여 특정 요소가 전환에 미치는 상대적 영향을 찾는 데 도움이 되며 효과적인 것으로 표시된 요소의 조합을 개선하는 데 도움이 될 수 있습니다.

**[!UICONTROL 다변량 테스트]**&#x200B;는 A/B 테스트와 비교하여 두 가지 이점을 제공합니다.

* 페이지에서 전환에 가장 큰 영향을 미치는 요소를 보여 주며, 이를 &quot;주요 효과&quot;라고도 합니다. 이 정보는 예를 들어 가장 많은 관심을 받을 콘텐츠를 배치할 위치를 결정하는 데 유용합니다.
* 이 플러그인은 페이지에서 두 개 이상의 요소 간에 복합 효과를 찾는 데 도움이 되며, 이를 &quot;상호 작용 효과&quot;라고도 합니다. 예를 들어, 특정 광고를 특정 배너 또는 영웅 이미지와 조합하면 더 많은 전환을 발생시킬 수 있습니다.

[!DNL Target]은 완전 요인 다변량 테스트를 사용하여 콘텐츠를 최적화하는 데 도움을 줍니다. 완전 요인 다변량 테스트는 동일한 확률로 가능한 모든 콘텐츠 조합을 검사합니다. 예를 들어, 페이지 요소에 오퍼가 3개씩 포함되어 있으면 총 9개의 조합을 만들 수 있습니다(3x3). 3개 요소 중 2개 요소에는 3개의 오퍼가 포함될 수 있으며 1개 요소에는 2개의 오퍼가 포함될 수 있으므로 총 18개의 옵션이 제공됩니다(3x3x2).

[!DNL Target]에서 각 조합은 하나의 경험입니다. **[!UICONTROL 다변량 테스트]**&#x200B;에서는 각 경험을 비교하여 가장 성공적인 조합을 알아볼 수 있습니다. 동시에 [!DNL Target]은(는) 데이터를 수집하고 분석하여 각 위치와 오퍼가 성공 지표에 미치는 영향을 파악합니다.

![다변량 테스트 조합](assets/multivariate.png)

생성할 수 있는 조합 수로 인해 **[!UICONTROL 다변량 테스트]**&#x200B;에는 A/B 테스트보다 더 많은 시간과 트래픽이 필요합니다. 페이지에서 충분한 트래픽을 수신해야 각 경험에 대해 통계상으로 유효한 결과를 얻을 수 있습니다. 유용한 결과를 얻으려면 페이지에 수신되는 트래픽의 양을 파악하고 적절한 시간에 대한 최적의 조합 수를 테스트하십시오.

[트래픽 견적 도구](/help/main/c-activities/c-multivariate-testing/t-create-multivariate-test/traffic-estimator.md#traffic-estimator)를 사용하면 트래픽을 사용한 테스트를 디자인할 수 있습니다. 사용하기 전에 사이트에서 일반적으로 수신하는 노출 횟수 및 전환 수를 보여주는 좋은 통계가 있어야 하며 일별 트래픽 수준을 고려해야 합니다. 활동에 경험이 많을수록 활동에 포함되어야 하는 트래픽이 많거나 실행해야 하는 시간이 길어집니다. 트래픽 양이 높지 않으면 몇 가지 조합을 테스트하십시오. 그렇지 않으면 의미 있는 테스트 결과를 생성하는 데 필요한 시간이 너무 길어 유용할 수 없습니다.

## MVT 용어 {#mvt-terminology}

여러 용어가 업계 전반에서 다른 방식으로 사용됩니다. 다음 표는 [!DNL Target]이(가) 다변량 테스트를 설정할 때 사용하는 용어를 정의합니다.

| 용어 | 정의 |
|--- |--- |
| 조합 | 여러 위치에서 여러 컨텐츠 옵션을 테스트할 때 만들어지는 컨텐츠 변형입니다. 예를 들어 각각 세 개의 콘텐츠 옵션이 있는 세 개의 위치를 테스트하는 경우 가능한 조합은 27개(3x3x3)입니다. 사이트 방문자에게는 경험이라고도 하는 하나의 조합이 표시됩니다. |
| 콘텐츠 | 위치 내에서 테스트 변형을 구성하는 텍스트 또는 이미지입니다. 다변량 테스트에서는 여러 위치 내의 몇 가지 콘텐츠 옵션을 비교합니다. MVT 방법론에서 콘텐츠는 때로 *수준*&#x200B;이라고도 합니다. |
| 요소 | MVT 테스트에서 테스트할 콘텐츠 변형을 포함하는 DOM 요소입니다. *위치*&#x200B;를 참조하십시오. |
| 위치 | 종종 단일 DOM 요소에 포함되는 페이지의 특정 콘텐츠 영역입니다. MVT 방법론에서 위치는 때로 *요인*&#x200B;이라고도 합니다. 전체 계승 다변량 테스트에서는 위치에 있는 오퍼들의 가능한 모든 조합을 비교합니다. |

## [!UICONTROL 다변량 테스트]와 A/B를 사용해야 하는 경우 {#when-to-use-mvt}

다음 표는 페이지를 최적화하기 위해 **[!UICONTROL 다변량 테스트]**, A/B 테스트 또는 두 테스트를 함께 사용하는 경우를 보여 줍니다.

| 상황 | 할 일 | 세부 사항 |
|--- |--- |--- |
| 테스트할 요소가 3개 미만입니다. | 일련의 A/B 테스트를 실행합니다. | 테스트할 요소가 3개 이상 있는 경우 MVT 테스트를 사용합니다. |
| 페이지의 레이아웃과 컨텐츠를 모두 최적화합니다. | A/B 테스트를 사용하여 페이지 레이아웃을 최적화한 다음 MVT 테스트를 사용하여 페이지의 각 요소에서 최상의 콘텐츠를 결정합니다. | A/B 테스트는 레이아웃에 대한 중요한 피드백을 제공할 수 있으며, MVT 테스트는 페이지 디자인에서 요소 내의 콘텐츠를 테스트할 때 탁월합니다. 여러 컨텐츠 옵션을 테스트하기 전에 레이아웃에서 A/B 테스트를 실행하면 최상의 레이아웃과 가장 영향력 있는 컨텐츠를 판별할 수 있습니다. |
| 서로 다른 경험의 수는 5개를 초과하며 둘 이상의 요소에 걸쳐 있습니다. | MVT 테스트를 사용하여 가장 중요한 요소를 파악한 후에 해당 요소에 좀 더 집중적인 A/B 테스트를 실행합니다. | MVT 테스트는 페이지에서 전환 개선 가능성이 가장 높은 영역을 보여줍니다. 마케터는 이러한 점에 중점을 두어야 합니다. 예를 들어, MVT 테스트는 클릭 유도 문안이 목표 달성을 위한 가장 중요한 요소임을 보여줄 수 있습니다. 그런 다음 A/B 테스트를 실행하여 두 개의 특정 이미지를 서로 테스트하거나 call to action의 문구 또는 색상을 비교하는 등 결과를 세분화할 수 있습니다. MVT 테스트를 하나 이상의 A/B 테스트와 함께 수행하여 원하는 결과에 대해 가능성이 가장 높은 콘텐츠를 결정할 수 있습니다. |

포함할 요소 수 및 테스트 계획 방법과 같은 추가 고려 사항은 [다변량 테스트 모범 사례](/help/main/c-activities/c-multivariate-testing/best-practices.md)를 참조하십시오.

## 부분 요인 테스트 {#partial-factorial}

[!DNL Target]에서는 기본 제공 활동 선택 사항으로 전체 계승 다변량 테스트를 제공합니다. 통계학의 &quot;실험 설계&quot;는 결과에 영향을 미치는 요인을 결정하기 위한 다양한 접근 방식 또는 설계를 제공합니다. 이러한 접근 방식은 부분 요인 테스트를 위한 [Taguchi 메서드](https://en.wikipedia.org/wiki/Taguchi_methods)입니다. Taguchi 메서드를 사용하면 마케터가 테스트해야 하는 경험의 순열 수를 줄여 다변량 테스트에 대한 트래픽 요구 사항을 감소시키는 일련의 가정을 세울 수 있습니다. 이 [오프라인 스프레드시트](/help/main/assets/MVT-Taguchi-Partial-Factorial-Design-02102017.xlsx)를 사용하여 [!DNL Target]에서 이 방법을 적용할 수 있습니다.

팀이 다른 실험 설계 접근 방식을 사용하는 경우 스프레드시트를 사용자 지정 실험 설계의 참조 구현으로 사용할 수 있습니다.

오프라인 계산 스프레드시트를 사용할 때에는 다음 팁을 고려하십시오.

* 변경할 요소와 각 요소의 버전 수(3x2, 4x3 등)를 선택합니다.
* 번호 지정 방식을 일관성 있게 유지합니다. 예를 들어, 단추가 요소 1이고 선택 사항이 파란색, 녹색 및 노란색인 경우 파란색 단추는 1-1, 녹색 단추는 1-2, 노란색 단추는 1-3이 됩니다.
* 오프라인 스프레드시트는 필요한 경험의 적절한 개수를 제공합니다(3x2의 경우 4개, 4x3의 경우 9개 등).
* [VEC(시각적 경험 작성기)](/help/main/c-experiences/experiences.md)를 사용하여 A/B 워크플로에서 경험을 구축합니다. 사용자 지정 코드를 사용하거나 HTML, WYSIWYG 또는 모든 조합을 편집할 수 있습니다.
* 활동이 끝나면(샘플 크기 계산기에 따라) 스프레드시트를 통해 결과를 실행하여 다른 세부 사항을 얻습니다.
