# 권장 사항 FAQ {#recommendations-faq}

>[!BEGINSHADEBOX]

**이 페이지에서:** [!DNL Adobe Target] [!DNL Recommendations] 활동에 대한 FAQ에 대한 답변을 찾아보세요.

>[!ENDSHADEBOX]

## 데이터 및 API {#data-and-apis}

+++ API를 통해 만든 [!DNL Recommendations]개의 개체가 [!DNL Target] UI에 표시됩니까?

예. API를 통해 만든 [!UICONTROL 권장 사항] 개체(**[!UICONTROL 기준]**, **[!UICONTROL 디자인]**, **[!UICONTROL 컬렉션]**, **[!UICONTROL 제외]**)는 UI에서 사용할 수 있으며 API 또는 [!DNL Target] UI를 통해 편집할 수 있습니다.

+++

+++ [!DNL Target] UI에서 만든 시각적 오퍼를 [!DNL Target] API로 관리할 수 있습니까?

아니오. [!DNL Target] UI에서 만들어진 시각적 오퍼가 있는 [!DNL Recommendations] 활동은 [!DNL Target] API로 관리할 수 없습니다. 이러한 활동은 **[!UICONTROL 활동]** 목록에 표시되지만 읽거나 업데이트할 수 없습니다(GET 또는 PUT 사용).

+++

+++ 제품을 삽입하거나 업데이트하는 API 호출의 크기 제한은 얼마입니까? 피드 대신 한 번의 호출로 50,000개의 제품을 업데이트할 수 있습니까?

[!DNL Target]은(는) 응용 프로그램 수준에서 50MB 게시물 제한을 지정하지만 `application/x-www-form-urlencoded` 콘텐츠 형식 헤더가 전달될 때만 적용됩니다.

50,000개의 제품이 있는 단일 호출을 시도할 수 있습니다. 호출이 실패하면 배치로 분할할 수 있습니다. Adobe은 시스템 로드로 인한 시간 초과 가능성을 줄이기 위해 5,000개 또는 10,000개 제품 배치를 권장합니다.

+++

+++ 피드 업로드를 위한 CSV 파일의 최대 크기는 얼마입니까?

피드 CSV 파일 업로드에 대한 행 수 또는 파일 크기에는 엄격한 제한이 없습니다. Adobe에서는 업로드 중 실패를 방지하기 위해 CSV 파일을 1GB로 제한하는 것이 좋습니다. 1GB를 초과하는 파일은 여러 피드 파일로 분할하는 것이 이상적입니다.

사용자 지정 속성 열의 최대 수는 100개이며 사용자 지정 속성은 4096자로 제한됩니다. 필수 열의 길이에 대한 다른 제한은 [[!DNL Target] 제한 페이지](/help/main/r-troubleshooting-target/target-limits.md)에서 확인할 수 있습니다.

+++

+++ 숫자 값이 있는 사용자 지정 특성을 검색할 때 **[!UICONTROL 카탈로그 검색]**&#x200B;에 올바른 결과가 표시되지 않는 이유는 무엇입니까?

숫자 값이 있는 사용자 지정 특성에 대해 카탈로그 검색이 수행되면 결과는 해당 특성을 숫자 값이 아닌 문자열로 처리합니다.

현재 고객이 속성 유형을 변경할 수 있는 기능을 사용할 수 없습니다. 변경하려면 문자열에서 숫자로 형식을 변경해야 하는 특성을 참조하는 [고객 문제를 여십시오](/help/main/cmp-resources-and-contact-information.md#reference_ACA3391A00EF467B87930A450050077C).

+++

## 시간 업데이트 {#update-timing}

+++ 카탈로그에 있는 항목에 대한 업데이트를 사이트에 반영하는 데 얼마나 걸립니까?

항목을 업데이트하는 방식에 따라 시간대와 결과가 다릅니다.

| 업데이트 | 추천 | 카탈로그 검색 |
| --- | --- | --- |
| mbox 또는 API를 통해 업데이트된 항목 속성 | 15분 이내 | 카탈로그 색인 후(3~8시간) |
| 피드를 통해 업데이트된 항목 속성 | 피드 수집 후(2~8시간) | 피드 수집(2~8시간) 및 후속 카탈로그 색인(3~8시간) 후 총 5~16시간 이내 |
| [!DNL Target] UI 또는 API를 통해 카탈로그에서 삭제된 항목 | 15분 이내 | 카탈로그 색인 후(3~8시간) |
| 항목이 mbox 또는 API를 통해 카탈로그에 추가됨 | 다음 알고리즘이 실행된 후에. 알고리즘 실행은 1~2일 알고리즘의 경우 12시간마다 예약되며, 7일 이상 알고리즘의 경우에는 24시간마다 예약됩니다 | 카탈로그 색인 후(3~8시간) |
| 항목이 피드를 통해 카탈로그에 추가됨 | 피드 수집(2~8시간) 및 후속 알고리즘이 실행된 후 1~2일 알고리즘의 경우 12시간마다, 7일 이상 알고리즘의 경우 24시간마다 총 2~32시간 이내에 예약됩니다 | 피드 수집(2~8시간) 및 카탈로그 색인(3~8시간) 후 총 5~16시간 이내 |

업데이트를 사용할 수 있을 때까지 다음 콘텐츠가 표시됩니다.

* 업데이트되거나 삭제된 항목에 대해 기존 권장 사항 및 항목 속성이 표시됩니다.
* 추가된 항목의 경우, 추가된 항목이 요청된 키가 아닌 경우 기존 권장 사항이 표시됩니다. 추가된 항목이 요청된 키인 경우 백업 권장 사항이 표시됩니다.

피드 파일을 가져온 후 또는 API나 mbox를 통해 엔티티 업데이트를 받은 후 60분 이내에 다음 변경 사항이 반영됩니다.

* 이전에는 제외되었지만 지금은 포함되어야 하는 경우에는 항목이 다음 알고리즘 실행에 포함됩니다(12~24시간).

  이 상황은 [!DNL Target]이 온라인과 오프라인 모두에서 제외를 적용하기 때문에 발생합니다. 항목을 새로 제외하는 경우에는 온라인 제외가 빠르게 적용됩니다. 항목이 새로 포함되면 온라인 제외는 빠르게 사라지지만, 오프라인 제외는 다음 알고리즘이 실행될 때까지 사라지지 않습니다.

* 이전에는 포함되었지만 지금은 제외되는 경우에는 소스에 따라 테이블의 시간표에 따라 항목이 제외됩니다. mbox 또는 API를 통해 15분, 피드를 통해 12~24시간.

다음 알고리즘 실행이 발생할 때까지(12~24시간 이내) 다음 변경 사항이 반영되지 않습니다.

* 활동의 컬렉션 규칙에 사용되는 항목 속성입니다.
* 속성 또는 활동과 연관된 컬렉션을 기반으로 하는 프로모션에 사용되는 항목 속성입니다.
* 항목이 **[!UICONTROL 최상위 판매자]** 또는 **[!UICONTROL 가장 많이 본 항목]** 알고리즘의 &quot;현재 범주&quot; 또는 &quot;즐겨 찾는 범주&quot;에 대해 표시되는 항목 범주입니다.
* 변경된 속성이 알고리즘에 대한 사용자 지정 키로 사용되는 사용자 지정 속성인 경우 권장되는 항목의 등급입니다.
* 하나 이상의 변경된 속성에 따라 권장되는 항목의 등급입니다. 권장 사항 로직이 &quot;속성이 비슷한 항목&quot;이거나 &quot;콘텐츠 유사성&quot; 또는 &quot;속성 가중치&quot; 요소가 사용되는 경우입니다.

>[!NOTE]
>
>피드 파일은 &quot;항목 가져오는 중&quot;에서 &quot;검색 색인 업데이트 준비 중&quot;으로 상태가 변경될 때 가져온 것으로 간주됩니다. 업데이트는 **[!UICONTROL 카탈로그 검색]** 사용자 인터페이스에 반영되는 데 60분 이상 걸릴 수 있습니다. 피드 상태가 &quot;업데이트 완료&quot;로 바뀌는 경우 **[!UICONTROL 카탈로그 검색]**&#x200B;이(가) 최신입니다. **[!UICONTROL 카탈로그 검색]**&#x200B;이 아직 최신 상태가 아닌 경우에도 위에 나열된 기간 내에 사이트에 업데이트가 반영됩니다. 가장 최근 **[!UICONTROL 카탈로그 검색]** 색인 업데이트 시간이 **[!UICONTROL 카탈로그 검색]** 페이지에 표시됩니다.

+++

+++ [!UICONTROL 권장 사항] 활동, 오퍼, 프로모션 또는 기준 설정의 구성 변경이 사이트에 반영되려면 얼마나 걸립니까?

* 프로모션 설정의 변경은 사이트에 반영되기까지 최대 5시간이 소요될 수 있습니다.
* 다른 기준 설정의 변경은 다음 알고리즘이 실행될 때까지 반영되지 않을 수 있음:

  * 동적 포함 규칙의 추가와 같은 일부 기준 설정은 즉시 반영됩니다.
  * 동적 포함 규칙의 제거 또는 전환 확인 기간 변경 등 다른 기준 설정은 다음 알고리즘이 실행될 때까지 통합될 수 없습니다.
  * 이러한 변경 사항은 알고리즘 실행을 트리거하며 완료하는 데 최대 24시간이 소요될 수 있습니다. 알고리즘도 12~24시간마다 일정에 따라 실행됩니다.

+++

+++ 사용자의 비헤이비어(예: A 제품을 클릭하고 B 제품을 구매)가 동일한 사용자가 받는 Recommendations에 반영되려면 얼마나 걸립니까?

* 현재 보거나 구매한 제품 또는 콘텐츠는 사용자가 같은 페이지 보기 또는 [!DNL Target] 콘텐츠 요청에서 받는 권장 사항에 영향을 줍니다.
* &quot;마지막으로 본 제품&quot;, &quot;가장 많이 본 제품&quot;, 전체 보기 및 구매 내역과 같은 역대 사용자 비헤이비어는 해당 요청으로 업데이트됩니다. 이는 사용자가 다음 페이지 보기 또는 콘텐츠 요청에서 받는 권장 사항에 영향을 줍니다. 예를 들어 **[!UICONTROL 최근에 본 항목]** 및 **[!UICONTROL 추천한 항목]** 알고리즘은 각 제품 보기 또는 구매로 업데이트되며, 업데이트는 후속 콘텐츠 요청에 반영됩니다.

+++

+++ 사용자의 행동이 다른 사용자가 받는 Recommendations에 반영되려면 얼마나 걸립니까?

집계된 사용자의 동작은 오프라인 알고리즘 처리에 통합됩니다. 이 처리는 12-24시간마다 모든 알고리즘 실행에서 발생합니다.

+++

+++ 최근에 본 항목 기반의 권장 사항은 단일 방문자에 대해 여러 디바이스에서 지속됩니까?

방문자가 세션을 시작하면 세션 ID가 단일 에지 컴퓨터에 연결되고 임시 프로필 캐시가 이 컴퓨터에 저장됩니다. 동일한 세션의 후속 요청에서는 최근에 본 항목을 포함하여 이 프로필 캐시를 읽습니다.

세션이 종료되면 최근에 본 항목을 포함한 세션 상태는 동일한 지리적 에지의 보다 영구적인 프로필 스토리지로 유지됩니다. 새 세션이 동일한 MCID(Marketing Cloud ID), ECID(Experience Cloud ID), CustomerID 또는 `mbox3rdPartyId`을(를) 통해 고객 프로필에 연결되어 있는 한 다른 디바이스의 후속 세션이 이러한 최근에 본 항목에 액세스할 수 있습니다.

방문자에게 동시에 두 개의 활성 세션이 있는 경우, 디바이스가 세션 ID를 강제로 공유하지 않는 한 한 한 디바이스의 최근에 본 항목은 다른 디바이스의 최근에 본 항목을 업데이트하지 않습니다. 잠재적인 해결 방법이 있지만 [!DNL Target]에서는 여러 장치에서 세션 ID의 공유를 직접 지원하지 않습니다. 고객은 이 ID 공유를 관리해야 합니다.

이 동작은 방문자가 한 디바이스에서 활성이고 몇 분 후에 다른 디바이스에서 활성이 되는 경우에도 발생합니다. 첫 번째 장치의 세션은 30분 동안 만료되지 않으며, 프로필 상태가 영구 상태에 기록되어 처리되기 전에 최대 5분의 지연이 발생할 수 있습니다. 이 동작을 테스트할 때 35분 안에 세션을 만료할 수 있으며 프로필을 저장할 수 있습니다.

방문자에게 동시에 두 개의 활성 세션이 없는 경우 세션이 종료된 동안 한 디바이스의 최근에 본 항목은 다른 디바이스의 최근에 본 항목을 업데이트합니다. 이 동작을 테스트할 때 35분 안에 세션을 만료할 수 있습니다.

+++

## 기준, 디자인 및 프로모션 {#criteria-designs-promotions}

+++ [!DNL Recommendations] 활동을 만들 때 사용자 지정 기준을 포함한 모든 기준을 선택할 수 없는 이유는 무엇입니까?

사용 가능한 기준은 현재 범주에 따라 다릅니다. 권장 사항 오퍼가 만들어지면 알고리즘 선택기는 카테고리 ID를 기반으로 기준을 표시합니다. 기준이 적용되는 위치에 카테고리 ID가 없으면 알고리즘 선택기에서 특정 기준을 사용할 수 없습니다. mbox에 카테고리 ID가 있는 위치를 사용하는 경우 기준 선택기는 적용 가능한 모든 기준을 포함합니다.

[!DNL Target]에 알고리즘 선택기의 지능적 필터링을 제어하는 [호환되지 않는 조건 필터링](https://experienceleague.adobe.com/docs/target-dev/developer/recommendations.html){target=_blank} 설정이 있습니다. **[!UICONTROL 호환되지 않는 기준 필터링]** 설정에 액세스하려면 **[!UICONTROL 관리]** > **[!UICONTROL 권장 사항]**&#x200B;을 클릭하십시오.

호환되지 않는 기준 필터링 옵션이 강조 표시된 ![권장 사항 설정 페이지](assets/recs_settings_filter.png)

* **[!UICONTROL 호환되지 않는 기준 필터링]** 설정이 사용되지 않는 경우 [!DNL Target]이(가) 알고리즘 선택기에서 알고리즘을 필터링하지 않고 모든 알고리즘이 표시됩니다.
* 이 설정을 사용하면 [!UICONTROL VEC(시각적 경험 작성기) ] 활동에서 [!DNL Target]이(가) 선택한 위치에서 entityId와 범주 ID를 읽습니다. 그러면 각 값이 해당 위치에 있는 경우 `currentItem|currentCategory`을(를) 기반으로 하는 알고리즘을 표시합니다. 따라서 선택한 위치와 호환되는 알고리즘만 기본적으로 알고리즘 선택기에 표시됩니다. 기준을 선택하는 동안 **[!UICONTROL 호환]** 확인란 선택을 취소하여 호환되지 않는 알고리즘을 계속 볼 수 있습니다.

  ![호환 확인란이 강조 표시된 기준 선택 화면](assets/compatible_checkbox.png)

[!DNL Target]은(는) 다음과 같은 특별한 경우에 **[!UICONTROL 호환]** 확인란을 표시하지 않습니다.

* entityId와 카테고리 ID가 모두 해당 위치에 있으므로 아무것도 필터링되지 않습니다.
* [!DNL mbox.js] 버전 55 이하가 사용됩니다.
* 페이지(`!config.isAutoCreateGlobalMbox && !config.isRegionalMbox`)에서 mbox 호출이 실행되지 않습니다.
* [!DNL Target] 매개 변수가 정의되지 않았습니다.

>**[!UICONTROL 호환되지 않는 기준 필터링]** 설정은 [!UICONTROL 시각적 경험 작성기]&#x200B;(VEC)에서 만들어진 활동에만 적용됩니다. [!DNL Target]에 위치 컨텍스트가 없으므로 이 설정은 **[!UICONTROL 양식 기반 경험 작성기]**&#x200B;에서 만들어진 활동에는 적용되지 않습니다.

+++ 일반 속성 가중치와 콘텐츠 유사성별 속성 가중치 간의 차이는 무엇입니까?

속성 가중치는 &quot;표준 속성 가중치&quot;와 &quot;콘텐츠 유사성 속성 가중치&quot;, 이렇게 두 가지 형태로 존재합니다.

* 표준 속성 가중치는 **[!UICONTROL 콘텐츠 유사성]**&#x200B;뿐만 아니라 대부분의 기준 유형에 적용됩니다. 이러한 유형의 가중치는 특정 속성 값에 더 많은 가중치를 부여합니다. 다음 예에서 Nike 제품은 출력 권장 사항에서 문제가 생깁니다.

* &quot;콘텐츠 유사성 특성 가중치&quot;는 **[!UICONTROL 콘텐츠 유사성]** 기준에만 적용됩니다. 이러한 유형의 가중치는 보다 역동적이며 현재 &quot;권장 사항 키&quot;(현재 표시된 항목)를 기반으로 합니다. 다음 예(브랜드 x 16)에서 Nike 스니커즈를 보는 방문자는 경쟁사의 스니커즈보다 다른 Nike 제품(반드시 스니커즈만 추천할 필요는 없음)을 추천받을 가능성이 높습니다. Adidas 스니커즈를 보는 방문자는 Adidas 제품을 추천받을 가능성이 더 큽니다.

+++ [!DNL Recommendations] 기준, 프로모션 또는 템플릿 테스트 규칙을 만들 때 mbox 이름을 지정해야 합니까?

mbox 매개 변수를 기반으로 [!DNL Recommendations] 기준, 승격 또는 템플릿 테스트 규칙을 만들 때 `mboxParameter`에서 더 이상 `mboxName`을(를) 묻는 메시지를 표시하지 않습니다. 이제 mbox 이름은 선택 사항입니다. 이 변경 사항을 사용하면 여러 mbox의 매개 변수 또는 에지에 아직 기록되지 않은 매개 변수에 대한 참조를 사용할 수 있습니다.

원하는 매개변수를 선택하려면 다음 방법 중 하나를 사용합니다.

* 기준, 프로모션 또는 템플릿 테스트 규칙을 생성하는 동안 목록에서 매개 변수 이름을 선택합니다. 매개 변수 이름의 첫 번째 문자를 입력하거나 전체 이름을 입력합니다.
* mbox 이름은 알려져 있지만 매개 변수 이름은 알려져 있지 않으면 확인란을 사용하여 원하는 매개 변수를 전달하는 알려진 mbox를 필터링합니다.

두 방법 중 하나를 사용하면 mbox와 매개 변수 간에 링크가 없습니다. 기준, 프로모션 또는 템플릿 테스트 규칙은 해당 매개 변수를 전달하는 모든 mbox에서 매개 변수를 기반으로 작동합니다.

기존 기준, 프로모션 또는 템플릿 테스트 규칙을 편집하면 필터링 시 생성 중에 제공된 mbox 이름이 표시됩니다.

+++ 엔티티를 동적으로 제외할 수 있습니까?

예. 권장 사항에서 제외할 엔티티의 엔티티 ID를 쿼리 문자열에 전달할 수 있습니다. 예를 들어 장바구니에 이미 있는 항목은 제외할 수 있습니다.

제외 기능을 활성화하려면 `excludedIds` mbox 매개 변수를 사용합니다. 이 매개 변수는 쉼표로 구분된 엔터티 ID 목록(예: `mboxCreate(..., "excludedIds=1,2,3,4,5")`)을 가리킵니다. 권장 사항이 요청되면 값이 전송됩니다.

제외는 현재 [!DNL Target] 호출에 대해서만 수행됩니다. `excludedIds` 값이 다시 전달되지 않는 한 후속 [!DNL Target] 호출에서 항목이 제외되지 않습니다. 장바구니의 항목을 모든 페이지의 권장 사항에서 제외하려면 모든 페이지의 `excludedIds` 값을 계속 전달하십시오.

`entityIds`을(를) 제외하려면 `&excludes=${mbox.excludedIds}` 토큰을 오퍼 콘텐츠 URL에 추가하십시오. 콘텐츠 URL이 추출되면 필수 매개 변수가 현재 mbox 요청 매개 변수로 대체됩니다.

기본적으로 이 기능은 새로 만든 권장 사항에 활성화되어 있습니다. 동적으로 제외된 엔티티를 지원하려면 기존 권장 사항을 저장해야 합니다.

>[!NOTE]
>
>너무 많은 엔티티가 제외되는 경우 권장 사항은 엔티티가 부족하여 권장 사항 템플릿을 채우지 못하는 것처럼 작동합니다.

+++ [!DNL Target]에서 권장 사항이 때때로 표시되지 않는 이유는 무엇입니까?

각 기준에 대해 생성된 값의 수는 디자인에 지정된 엔티티 수의 3배입니다. 런타임 필터링(예: 재고 또는 mbox 속성 일치)은 3x개의 값이 생성된 후에 적용되므로, 전달 시 3x개 미만의 값이 남아 있을 수 있습니다. 이 상황을 완화하려면 추가 엔티티를 숨겨서 디자인의 엔티티 수를 늘리십시오.

 #if( $foreach.count > 10 ) 
  #break 
 #end

+++ [!DNL Recommendations] 콘텐츠 추적에서 가끔 반환되는 NO_CONTENT 응답은 무엇을 의미합니까?

요청한 알고리즘 및 키 조합에 대한 권장 사항을 사용할 수 없는 경우 NO_CONTENT가 반환됩니다. 일반적으로 이러한 상황은 알고리즘에 대해 백업이 비활성화되고 다음 조건 중 하나 이상이 참인 경우에 발생합니다.

* 결과가 아직 준비되지 않았습니다.

  일반적으로 이러한 상황은 새로 만든 활동을 처음 저장하거나 활동에 사용된 컬렉션, 기준 또는 프로모션에 대한 구성이 변경된 후에 발생합니다.

* 요청된 알고리즘 및 키 조합에 대해 가장 가까운 에지 서버에 아직 캐시되지 않은 결과가 준비됩니다.

  요청이 캐싱 작업을 시작하므로 이 문제는 몇 페이지를 다시 로드하거나 몇 분 후에 해결됩니다.

* 결과가 준비되었지만 제공된 키 값에 대해 사용할 수 없습니다.

  일반적으로 이러한 상황은 가장 최근 알고리즘 실행 후 카탈로그에 추가된 항목에 대한 권장 사항이 요청될 때 발생합니다. 다음 알고리즘이 실행된 후에 확인됩니다.

* 부분 템플릿 렌더링이 비활성화되며 템플릿을 채우기에는 결과가 충분하지 않습니다.

  일반적으로 이 상황은 가능한 결과에서 많은 항목을 적극적으로 필터링하는 동적 포함 규칙에서 발생합니다. 이러한 상황을 방지하려면 백업을 활성화하고 백업에 포함 규칙을 적용하지 않거나 덜 적극적으로 필터링된 기준을 순서대로 사용하십시오.

+++ [!DNL Recommendations]의 컬렉션이 0이 되면 어떻게 해야 합니까?

이전에 0이 아니었던 컬렉션이 0이 되면 다음 사항을 고려하십시오.

* 컬렉션을 다시 저장하고 번호가 업데이트되는지 확인합니다. 다시 저장하면 해당 컬렉션을 사용하는 모든 알고리즘이 다시 실행됩니다.
* 올바른 환경이 표시되는지 확인합니다. **[!UICONTROL 관리]** > **[!UICONTROL 권장 사항]**&#x200B;을 클릭한 다음 **[!UICONTROL 제품 카탈로그]** 섹션에서 **[!UICONTROL 기본 호스트 그룹]** 설정을 확인하십시오.

  제품 카탈로그 섹션에서 기본 호스트 그룹 드롭다운이 강조 표시된 관리 탭의 ![권장 사항 페이지](../assets/reco_faq_1.png)

* 색인이 최신 상태인지 확인합니다. **[!UICONTROL 권장 사항]** > **[!UICONTROL 카탈로그 검색]**&#x200B;을 클릭하고 색인이 몇 시간 경과되었는지 확인합니다(예: &quot;색인화된 후 3시간 경과&quot;). 필요에 따라 인덱스를 새로 고칠 수 있습니다.
* 피드나 데이터 레이어에서 변경된 사항이 있어 더 이상 수집 규칙과 일치하지 않는 엔티티가 발생했는지 확인합니다. 대소문자가 일치하는지(규칙은 대소문자를 구분함) 확인합니다.
* 피드가 성공적으로 실행되었는지 또는 누군가 FTP 디렉터리, 암호 등을 변경했는지 확인합니다.
* [!DNL Target]은(는) 고객 페이지 또는 앱에서 가능한 한 빨리 게재를 업데이트하며 마케터를 위해 UI에 표시를 제공해야 합니다. [!DNL Target]은 UI 업데이트가 동기화되는 것을 기다리기 위해 게재 업데이트를 지연하지 않습니다. [mboxTrace](/help/main/c-activities/c-troubleshooting-activities/content-trouble.md)을(를) 사용하여 요청이 들어올 당시 시스템의 내용을 확인합니다.

+++ [!DNL Recommendations] 활동에서 **[!UICONTROL 데이터 다운로드]** 작업이 실패한 이유는 무엇입니까?

[!DNL Recommendations] 활동의 **[!UICONTROL 활동 개요]** 페이지에서 **[!UICONTROL 데이터 다운로드]**&#x200B;를 클릭하면 [!DNL Target] 사용자 인터페이스에 `Error while fetching recommendation data file.` 오류가 표시될 수 있습니다

이 오류는 일반적으로 활동에 매우 큰 결과 세트가 있을 때 발생합니다. 생성된 CSV가 단일 다운로드에서 사용자 인터페이스를 통해 반환할 수 있는 응답 크기를 초과합니다. 권장 사항 데이터 자체는 그대로 유지됩니다. 브라우저 내 다운로드 경로만 해당 크기의 파일을 전달할 수 없습니다.

## 알려진 문제 {#known-issues}

다음은 [!UICONTROL 권장 사항] 활동에 대한 알려진 문제입니다.

* [!DNL Target]이(가) `getOffer()`과(와) 함께 JSON 오퍼를 반환하면 JSON 형식을 반환합니다. 그러나 JSON [!DNL Recommendations] 디자인은 HTML 형식을 반환합니다.
* 피드나 API를 통해 업데이트를 받지 못한 후 60일이 지나면 만료된 엔티티가 올바르게 만료됩니다. 그러나 만료된 엔터티는 만료 후 **[!UICONTROL 카탈로그 검색]** 인덱스에서 제거되지 않습니다. 피드 또는 API를 통해 삭제된 엔터티도 현재 **[!UICONTROL 카탈로그 검색]** 색인에서 제거되지 않습니다. (IRI-857)
* A/B 및 Experience 타기팅 활동의 [!DNL Recommendations]개 오퍼는 [!DNL Recommendations] 트레이의 시각적 미리 보기를 표시하지 않습니다. (TGT-33426)
* 기준 목록(카드) 보기에 표시된 사용자 지정 기준 피드 상태는 10분마다 새로 고침되며 특수한 상황에서 10분 이상 걸릴 수 있습니다. 사용자 정의 기준 편집 보기에 표시된 상태를 실시간으로 가져오며 상태는 항상 최신입니다. (TGT-35896, TGT-36173)
